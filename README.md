# 키온 (key:on)

일반 블로거의 키워드 탐색·블로그 분석과 네이버 인플루언서의 모든 분야 키워드 챌린지·순위 관리를 제공하는 웹앱입니다. 서비스 이름은 **키온(key:on)**, 대시보드 제목은 **키온 대시보드**입니다. 로고의 `on`을 보라색으로 강조하며 주요 메뉴는 대시보드 → 내 블로그 분석 → 키워드 검색 → 보관함 순서입니다. 공용 목록은 로그인 없이 검색할 수 있고, 개인 데이터는 Supabase Auth와 RLS를 통해 분리됩니다.

## 포함 기능

- 첫 화면의 전략 대시보드: 전체 키챌·내 참여·TOP3·4~10위 지표와 오늘의 공략 TOP10
- 키워드 기회 찾기: 블루오션·롱테일·레드오션 후보, 내 분야·미참여 우선, 추천 이유와 보관함 담기
- 실제 수집일 기준 오늘의 순위변동: 상승/하락·신규 TOP3/이탈과 키워드별 일별 이력
- 분야·참여 상태·참여자·순위·콘텐츠 수·월 검색량 상세필터와 키워드별 상세 보기
- 네이버 검색광고 실제 PC+모바일 월 검색량 및 검색량 높은 미참여 TOP10
- 이메일/비밀번호 계정 생성과 로그인
- 로그인한 계정의 인플루언서별 키챌 데이터 저장
- 키워드 검색, 순위 필터, 정렬
- JSON 백업 내보내기와 가져오기
- 인플홈 주소 입력 후 버튼 한 번으로 공개 참여 키워드 자동 수집
- 수집 진행률 표시·취소, 전체 수집 완료 후 계정별 저장
- 매일 오전 4시(한국시간)부터 공용 목록과 저장된 인플홈의 참여 키워드·순위 예약 갱신
- 인플홈별 예약 켜기/끄기와 마지막 갱신·오류 상태 표시
- 분야·참여자 수·키워드 이름으로 전체 목록 검색 (서버 검색, 50개씩 페이지 표시)
- 내 인플홈 수집 결과와 키워드 ID를 비교하여 참여·미참여 및 순위 표시
- 관리자만 공용 목록 JSON 등록 가능, 업로드 완료 후 한 번에 공개
- 목록의 수집 범위·분야별 개수·기준일 표시

## 1. Supabase 설정

1. 본인 Supabase 조직에서 새 프로젝트를 만듭니다.
2. `supabase/migrations/`의 SQL 파일을 시간순으로 적용합니다. 기존 배포에는 새 마이그레이션만 적용합니다.
3. Authentication → URL Configuration에서 배포한 사이트 주소를 Site URL과 Redirect URLs에 등록합니다.
4. 프로젝트 URL과 공개용 anon key를 Vercel 프로젝트 환경 변수 `SUPABASE_URL`, `SUPABASE_ANON_KEY`로 등록합니다. 이 두 값은 브라우저에 포함됩니다. 테이블 접근은 RLS 정책이 보호하므로 service role key를 프런트엔드에 넣지 마세요.

계정 확인 이메일 기능은 Supabase Auth 설정에 따릅니다. 사용자는 인증 이메일을 확인한 뒤 로그인할 수 있습니다.

## 2. 자동 수집 Edge Function 배포

Supabase CLI로 로그인하고 프로젝트를 연결한 뒤:

```sh
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy keychallenge-collect
```

Supabase가 제공하는 기본 환경 변수 `SUPABASE_URL`, `SUPABASE_ANON_KEY`를 사용합니다. 자동 수집 함수는 service role key를 사용하지 않습니다. `verify_jwt = true`를 유지하며 함수 내부에서도 `auth.getUser()`로 로그인 사용자를 확인합니다.

함수는 네이버 공개 인플홈에서 소유자 ID를 확인한 뒤 공개 참여 목록을 100개씩 가져옵니다. 네이버 로그인 정보나 쿠키는 필요하지 않습니다. 프런트엔드는 진행률을 표시하고 전체 개수가 일치하는 경우에만 로그인한 사용자의 RLS 권한으로 저장합니다. 실패하거나 취소하면 기존 저장 데이터는 유지됩니다. 네이버 요청 제한 응답은 사용자에게 안내하며 자동 우회하지 않습니다.

기존 `keychallenge-handoff` 함수와 관련 마이그레이션은 이전 배포와의 호환성을 위해 남아 있습니다. 현재 화면은 이 함수를 호출하지 않습니다.

## 3. Vercel 배포

1. 이 GitHub 저장소를 Vercel에 연결합니다.
2. Vercel Project Settings → Environment Variables에 `SUPABASE_URL`, `SUPABASE_ANON_KEY`를 추가합니다.
3. 빌드 명령은 `npm run build`, 출력 폴더는 `dist`입니다. [`vercel.json`](vercel.json)에 설정되어 있습니다.
4. 배포된 주소를 Supabase Auth의 Site URL 및 Redirect URLs에도 등록합니다.

환경 변수를 로컬에서 시험하려면 `.env.example`을 참고해 `.env`를 만들고, `npm run build`를 실행합니다. `.env`와 생성된 `dist/config.js`는 Git에 올리지 않습니다.

## 4. 데이터 수집

1. 배포된 사이트에서 계정을 만들고 로그인합니다.
2. 인플루언서 ID 또는 `in.naver.com/...` 주소를 입력한 뒤 **자동 수집 시작**을 누릅니다.
3. 진행률을 확인하고 완료될 때까지 사이트를 열어 둡니다. 필요하면 **수집 취소**를 누를 수 있습니다.
4. 완료되면 해당 계정에 저장되고 전체 목록에서 참여 여부와 순위를 비교할 수 있습니다.

개발자 도구를 열거나 코드를 복사할 필요가 없습니다. 바로 갱신하려면 같은 버튼을 다시 누릅니다. 저장된 인플홈은 기본적으로 매일 오전 4시(한국시간)부터 순차 갱신됩니다. ‘매일 오전 4시 자동 갱신’ 설정을 끄면 해당 인플홈의 예약을 중지합니다. 예약 수집은 사이트와 컴퓨터를 꺼 두어도 서버에서 실행됩니다.

네이버 서비스의 화면/API 동작이 바뀌면 수집기 코드를 다시 조정해야 할 수 있습니다. 이 도구는 네이버 공식 서비스가 아닙니다.

## 5. 관리자 지정

관리자도 사이트 계정으로 로그인합니다. 네이버 계정의 분야와는 관계가 없습니다.
`keychallenge_admins`에 등록된 사용자만 공용 목록을 등록할 수 있으며, 일반 사용자에게 이 테이블의 쓰기 권한은 없습니다.
이메일 인증을 완료한 사용자를 Supabase SQL Editor에서 지정합니다 (이메일은 실제 관리자 이메일로 바꾸세요).

```sql
insert into public.keychallenge_admins(user_id)
select id from auth.users
where lower(email) = lower('ADMIN_EMAIL_HERE') and email_confirmed_at is not null
on conflict(user_id) do nothing;
```

관리자 역할은 공용 목록 관리와 공용 검색광고 API 연결을 허용합니다. 다른 회원의 개인 수집 데이터를 볼 수 있는 권한을 부여하지 않습니다.

## 6. 전체 키워드 목록 갱신

Python 3의 기본 라이브러리로 네이버 공개 목록을 수집합니다. 로그인 쿠키를 사용하지 않으며 키워드 ID·이름·분야·참여자 수만 가져옵니다.

```sh
python3 scripts/fetch-naver-catalog.py /absolute/path/naver-catalog.json
```

1. 공개된 분야 목록을 가져온 뒤 각 분야를 순서대로 수집합니다.
2. 일반 목록과 별도 미션 목록을 합치고, 페이지마다 간격을 두어 수집합니다. 고유 ID 개수가 원본의 표시 총계와 다르면 최대 두 번 더 읽어 보완합니다. 계속 차이가 있으면 실제 제공된 목록을 보관하고 `coverage: partial`, 분야별 `discrepancies`, 출처 문구에 차이를 기록합니다. 누락 항목을 만들어 채우지 않습니다.
3. 완료된 분야는 같은 경로의 `.checkpoint.json`에 보관합니다. 중단 후 같은 출력 경로로 실행하면 이어받습니다. **새 기준일의 전체 갱신에는 새 출력 파일명을 사용하세요.**
4. 사이트에 관리자 계정으로 로그인 → ‘목록 관리’ → 생성된 JSON 선택 → 수집 범위와 기준일 확인 → 공개.

파일 형식은 `{ "source": "출처", "coverage": "all 또는 partial", "collectedAt": "ISO 날짜", "items": [...] }`입니다. 각 items 항목은 `id`, `name`, `field`, `fieldGroup`, `categoryId`, `participantCount`를 사용합니다. 기존 `allKeywords` 백업도 지원합니다. 출처의 완전성을 확인한 경우에만 `all`을 사용하세요.

업로드 중에는 이전 공개 목록을 유지합니다. 업로드가 끝나면 서버에서 행 개수를 확인한 뒤 공개 목록 포인터를 변경합니다. 이전 스냅샷과 미완료 업로드는 자동 삭제하지 않습니다. 필요할 때 관리자 데이터베이스 작업으로 정리하세요.

### 해석 범위

- 전체 목록과 순위는 수집 시점의 스냅샷입니다. 예약 수집은 매일 오전 4시에 시작되며 처리량에 따라 완료 시간이 달라집니다.
- 공개 API는 네이버가 변경할 수 있는 내부 인터페이스입니다. 응답 구조가 바뀌면 수집 스크립트를 조정해야 합니다.
- `challengeable`은 로그인 계정에 따라 달라질 수 있어 공용 목록에 저장하지 않습니다. 키워드 검색 가능 여부와 네이버에서 실제 참여 가능한 분야는 구분합니다.
- ‘미참여’와 순위는 마지막 개인 수집 데이터 기준입니다. 총개수를 확인할 수 없거나 일부만 저장한 데이터는 ‘기록 없음’으로 표시합니다.

## 7. 매일 예약 갱신 운영

`add_daily_refresh` 마이그레이션을 적용한 뒤 서버 함수를 배포합니다.

```sh
supabase functions deploy keychallenge-sync
```

프로젝트의 SQL Editor에서 활성화합니다. 현재 운영 프로젝트에는 이미 활성화되어 있습니다.

```sql
update public.keychallenge_refresh_schedule set enabled = true where singleton;
-- 처음 한 번은 즉시 수집을 시작할 수 있습니다.
select keychallenge_private.enqueue_daily();
select keychallenge_private.dispatch_sync();
```

- `keychallenge-daily-refresh`: UTC 19:00 = 한국시간 다음 날 오전 4시에 공용 목록과 예약을 켠 인플홈을 작업 대기열에 넣습니다.
- `keychallenge-refresh-worker`: 30초마다 대기 작업이 있는지 확인합니다. 작업이 있을 때만 서버 함수를 호출하고, 페이지별 진행 위치를 저장해 이어갑니다.
- 서버 함수는 별도의 256비트 비밀값으로 인증합니다. 비밀값은 DB에서 생성해 Vault에 보관하며, 함수는 해시를 비교한 뒤에만 작업을 가져갑니다. `verify_jwt = false`인 이유는 이 별도 서버 인증을 사용하기 때문입니다. 일반 회원·익명 사용자는 대기열·인증 테이블·작업 RPC에 접근할 수 없습니다. 서비스 키는 Supabase 함수 런타임에서만 사용됩니다.
- 중복 작업은 임대 잠금으로 제한합니다. 오류는 5/15/45분 간격으로 최대 3회 재시도하고, 네이버 요청 제한은 최소 15분 대기합니다. 실패하면 기존 데이터를 유지하고 상태를 표시합니다.
- 개인 데이터는 총개수가 일치할 때만 저장합니다. 수집 도중 사용자가 직접 갱신하거나 예약을 끄면 그 변경을 우선합니다.
- 공용 목록은 20개 분야를 현재 네이버 분야 목록 기준으로 수집합니다. 분야별 일반 목록과 미션 목록을 합치고, 개수가 다르면 페이지 크기를 바꾸어 최대 두 번 보완합니다. 작은 원본 차이는 `partial`과 실제 차이로 표시하며, 누락이 큰 경우 공개하지 않습니다.
- 모든 분야의 수집이 완료된 다음 한 번에 공개 목록을 교체합니다. 자동 생성 스냅샷은 최근 3개를 유지하며, 기존 수동 등록 스냅샷은 유지합니다.
- 전체 예약을 중지하려면 `keychallenge_refresh_schedule.enabled`를 `false`로 변경합니다. 이미 진행 중인 요청은 현재 처리 구간을 마친 뒤 중지합니다.

운영 상태 확인:

```sql
select jobname, schedule, active from cron.job where jobname like 'keychallenge-%';
select kind, status, attempts, last_error, updated_at, completed_at
from public.keychallenge_sync_jobs;
```

다른 Supabase 프로젝트에 설치할 때는 마이그레이션의 `dispatch_sync()`에 있는 프로젝트 URL도 해당 프로젝트의 URL로 변경하세요.

## 8. 전략 대시보드와 일별 이력

공유·즐겨찾기에는 사이트의 기본 주소(`/`)를 사용합니다. 로그아웃 상태에서는 기본 주소에 로그인·가입 화면을 표시하고, 로그인한 상태에서는 선택한 이용 유형의 대시보드를 표시합니다. 별도 수집·예약 관리 메뉴는 없으며 인플홈 연결·갱신 설정은 `내 설정 → 인플홈 관리`에 있습니다. 기존 `#mySpace` 주소는 `#accountView`로 연결합니다. 공용 키워드 목록은 로그인 없이 검색할 수 있습니다.

대시보드는 내 주요 분야를 자동 선택하며 모든 분야 또는 특정 분야로 바꿀 수 있습니다. 지표를 누르면 해당 조건의 상세 목록이 열립니다. 인플홈 연결·수동 갱신·예약 설정·백업은 내 설정의 인플홈 관리에서 이용합니다. 인플루언서 유형에만 표시하며, 일별 순위 기록을 위한 오전 4시 예약은 유지합니다. 블로그 글의 로그인 시 수집과는 별도입니다.

가입 후 첫 로그인에는 이용 유형을 선택합니다. 인플루언서로 선택하고 저장된 인플홈이 없으면 **인플홈 연결하기** 안내를 표시합니다. 주소를 입력해 첫 수집과 저장을 완료하면 대시보드로 이동합니다. 이미 연결한 계정은 로그인 후 바로 대시보드가 열립니다. 연결 정보를 불러오는 중이거나 조회에 실패한 경우에는 신규 연결 안내 대신 해당 상태를 표시합니다.

- 완전한 개인 수집 결과가 저장될 때 한국시간 날짜별 순위 스냅샷을 남깁니다. 같은 날짜에는 가장 최근 결과를 유지하고 32일간 보관합니다.
- 최초 설치 시 현재 실제 수집 기록만 기준으로 저장합니다. 과거 순위를 만들어 채우지 않으며, 다른 날짜의 수집이 쌓인 뒤 변화가 표시됩니다.
- 오늘의 공략은 4~10위에서 TOP3와의 거리, 이전 기록 대비 상승, 참여자 수, 콘텐츠 수와 수집된 월 검색량을 조합합니다. 화면에서 산정 기준을 볼 수 있습니다.
- 미참여는 현재 공개 목록과 완전한 개인 수집 결과의 키워드 ID 차집합입니다. 네이버에서 실제 참여할 자격을 의미하지 않습니다.
- 본인 이력만 조회할 수 있습니다. 비로그인 사용자에게는 공용 키워드 목록과 공용 검색량만 공개됩니다.
- `optimize_strategy_dashboard_queries`는 개인 순위 JSON을 한 번 펼친 뒤 공용 목록과 조인하고, 분야 매핑을 한 번만 집계합니다. 제거된 순위 변화 그래프의 전체 이력 집계는 실행하지 않습니다. 오늘의 순위변동과 키워드별 일별 이력은 유지하며 기존 조회 제한 시간과 본인 데이터 접근 권한은 변경하지 않습니다.

## 9. 네이버 검색광고 월 검색량 연결

`add_strategy_dashboard`, `add_search_volume_ingestion` 마이그레이션을 적용하고 두 함수를 배포합니다.

```sh
supabase functions deploy keychallenge-searchad
supabase functions deploy keychallenge-sync
```

1. 관리자 계정으로 로그인하고 **관리자 설정 → 네이버 검색광고 연결**을 엽니다.
2. 본인의 검색광고 API 관리 화면에서 발급한 고객 ID(Customer ID), API License, Secret Key를 이 관리자 폼에 직접 입력합니다. 채팅이나 GitHub에 키를 붙여넣지 않습니다.
3. **연결 저장 · 검색량 수집 시작**을 누릅니다. 공식 검색광고 API에서 실제 응답을 받은 후에만 연결을 저장합니다.
4. 서버가 현재 공개 키워드에 해당하는 결과를 저장하고 나머지를 순차 수집합니다. 일반 사용자는 API를 연결할 필요가 없습니다.

API 키는 Supabase Vault에 암호화해 보관합니다. 관리자 로그인과 DB 관리자 역할을 확인한 서버 함수만 연결을 수정할 수 있고, 저장된 키를 브라우저로 반환하는 기능은 없습니다. 조회 요청은 공식 `https://api.searchad.naver.com/keywordstool`로만 전송합니다.

- `keychallenge-daily-search-volume`은 매일 한국시간 오전 4시 15분에 시작합니다. 등록된 인플홈의 분야를 먼저 처리하고, 하루 최대 4,000개의 조회 키워드를 다룹니다. 응답에 포함된 관련 키워드도 공개 목록과 일치하면 저장합니다.
- 미수집 또는 30일이 지난 검색량을 우선 갱신합니다. 11만 개 이상의 목록을 하루 만에 모두 수집한다고 보장하지 않습니다. 화면에는 수집된 검색량 범위가 표시됩니다.
- 월 검색량은 PC+모바일 합계입니다. 네이버가 `<10`으로 제공하면 0~9 범위를 합산하여 표시합니다. 결과가 없는 키워드는 ‘미수집’으로 남기며 0으로 간주하지 않습니다.
- ‘검색량 높은 미참여 TOP10’은 검색량이 확인된 키워드 내에서 정합니다. 월 검색량은 일별 검색량이 아니며, 네이버가 제공하는 시점의 최근 월간 지표입니다.
- 연결 화면에서 검색량 수집을 일시 중지할 수 있습니다. 다시 연결을 저장하면 재개됩니다. 키워드·순위 자동 수집과 검색량 수집은 각각 관리합니다.


## 비밀번호 재설정 메일 설정

- 로그인 화면의 **비밀번호를 잊으셨나요?** 또는 **내 설정 → 비밀번호 재설정**에서 `/password-reset.html`로 이동합니다. 가입한 이메일로 링크를 요청하고, 해당 링크를 열면 새 비밀번호와 확인 값을 입력합니다.
- Supabase **Authentication → URL Configuration**에서 Site URL을 `https://keyon.vercel.app`로 설정하고 Redirect URLs에 `https://keyon.vercel.app/password-reset.html`을 추가합니다. 다른 도메인에 설치할 때는 해당 도메인의 동일 경로를 허용합니다.
- **Authentication → Emails → SMTP Settings**에서 운영용 발송 서버를 연결해야 일반 회원에게 메일을 보낼 수 있습니다. 기본 Supabase 메일 서버는 조직 팀원 주소로만 발송이 허용되므로 일반 회원용으로 사용할 수 없습니다. SMTP 비밀번호는 대시보드에 직접 입력하며 소스·로그·채팅에 남기지 않습니다.
- Reset password 메일 템플릿의 링크에는 기본 `{{ .ConfirmationURL }}`을 유지합니다. 인증 검증을 건너뛰는 직접 페이지 링크로 바꾸지 않습니다. 메일 제공자의 링크 추적은 인증 링크를 변형할 수 있으므로 사용하지 않습니다.
- 재설정 클라이언트는 기존 대시보드 로그인과 다른 키 및 `sessionStorage`를 사용합니다. 이메일의 recovery 토큰으로 서버에서 사용자를 확인한 경우에만 비밀번호 입력 화면을 열며, 새 링크 오류 시 이전 재설정 세션을 재사용하지 않습니다. 새로고침은 같은 탭에서 지원하고, 저장 후 이 재설정 세션을 종료합니다.
- 이메일 등록 여부를 노출하지 않는 요청 완료 문구, 60초 재발송 대기, 만료·사용된 링크 재요청, 8자 이상 및 비밀번호 확인 입력을 제공합니다. 실제 발송 제한은 Supabase/SMTP 제공자의 서버 설정을 따릅니다. 키온은 기존 비밀번호를 조회하거나 표시하지 않습니다.
- 공개 페이지와 콜백 구성의 배포만으로 메일 전달까지 확인된 것은 아닙니다. 실제 메일 수신·링크 이동·저장 확인은 SMTP 연결 후 허용된 계정으로 별도로 진행합니다.

## 10. 일반 블로거와 공통 글감 작업 공간

`add_blogger_workspace` 마이그레이션을 적용하고 `keychallenge-keyword-search` 함수를 배포한 뒤 프런트엔드를 배포합니다.

- 기존 인플홈을 보유한 회원은 인플루언서 유형으로 유지합니다. 신규 회원은 일반 블로거 / 인플루언서를 선택하며 **내 설정**에서 바꿀 수 있습니다. 이용 유형은 화면 설정이며 관리자 권한을 부여하지 않습니다.
- 일반 블로거는 네이버 블로그 주소와 관심 분야를 등록합니다. 주소 등록 방식이며 네이버 로그인 연동·소유권 인증·방문자 통계 수집 기능은 포함하지 않습니다.
- 일반 대시보드는 내 블로그 분석(최근 글·검색 노출·발행 흐름)을 표시합니다. 인플루언서의 기존 순위 대시보드는 유지합니다.
- **키워드 검색**은 관리자에게 연결된 공식 네이버 검색광고 API를 사용합니다. 인플루언서 카탈로그 밖의 검색어와 관련 키워드 최대 200개, PC/모바일 월 검색량을 보여줍니다. `<10`은 0~9 범위이며, 데이터 없음은 0이 아닌 미확인으로 표시합니다.
- 30일 이내 조회는 공용 캐시를 활용합니다. 새 외부 조회는 사용자당 분당 10회 / 한국시간 하루 100회로 제한합니다. 캐시·사용량은 서버 전용이며 검색광고 비밀키는 기존 Vault에서만 읽습니다.
- **보관함**은 키워드 중복을 정규화하여 방지하고 폴더·메모·검색·보관 해제/복원을 제공합니다. 보관 해제해도 연결된 계획은 유지합니다.
- 기존 **발행 계획** 메뉴는 **내 블로그 분석**으로 교체했습니다. 이전 계획 데이터와 관련 RPC는 보존하며, 기존 `#plannerView` 링크는 분석 화면으로 연결됩니다.
- 개인 설정·키워드·계획 테이블에는 본인 UID 기반 RLS가 적용됩니다. 개인 RPC는 security invoker이며, 다른 회원의 키워드에 계획을 연결할 수 없도록 복합 외래 키를 사용합니다.
- 두 유형 모두 같은 키워드 검색·보관함·내 블로그 분석 메뉴를 사용합니다. 유형을 바꾸어도 기존 키워드·계획·인플홈 기록은 유지됩니다.

## 11. 회원 관리와 이용 등급

`add_membership_management` 마이그레이션 적용 후 `keychallenge-keyword-search`, `keychallenge-collect`를 배포하고 프런트엔드를 배포합니다. 회원 유형(블로거/인플루언서), 이용 등급(기본/플러스), 관리자 권한은 서로 독립적입니다.

- 관리자 메뉴 **회원 관리** (`#memberAdmin`)에서 이메일·블로그 ID 검색, 현재 적용 등급·만료 회원 필터, 가입일·이메일 인증·최근 로그인 확인, 회원별 사용량과 연결 인플홈 확인을 제공합니다.
- 회원 상세에서 기본/플러스, 플러스 시작일·만료일, 관리자 전용 메모를 저장합니다. 변경 사유는 필수이고 변경 전후 값과 작업자를 기록합니다. 관리자 권한을 부여하는 UI나 회원 삭제 기능은 포함하지 않습니다.
- 신규 회원은 기본 등급입니다. 기존 회원도 기본 등급으로 유지합니다. 첫 이용 시 필요한 기본 기록을 만들므로 Auth 가입 트리거에 의존하지 않습니다.
- **현재 두 등급 모두 기존 기능을 무료로 제공**합니다. 초기 한도는 동일합니다: 새 외부 검색량 조회 하루 100회, 보관 키워드·발행 계획·연결 인플홈은 제한 없음. 플러스 지정만으로 결제가 발생하지 않습니다.
- 등급별 한도 입력에서 빈칸은 무제한, 0은 새 조회/추가·복원 제한입니다. 보관 해제한 키워드와 숨긴 계획은 수량에서 제외됩니다. 기존 데이터는 한도를 낮춰도 삭제되지 않고 조회·수정할 수 있습니다. 기존 인플홈의 수집·예약 갱신도 유지됩니다.
- 검색량 한도는 기존처럼 캐시가 없는 외부 조회 요청에만 적용되며, 실패한 외부 시도도 횟수에 포함됩니다. 공유 캐시 결과는 횟수에서 제외됩니다. 하루는 한국시간 기준이고 분당 10회 제한은 모든 등급에 동일하게 유지합니다.
- 플러스 시작일·만료일은 한국시간 날짜입니다. 만료일 당일까지 적용되고 다음 날부터 기본 한도를 사용합니다. 요청 시 서버가 유효 기간을 판정하므로 별도 만료 작업 지연이 없습니다. 배정 이력은 보존되어 관리자가 만료 상태를 볼 수 있습니다.
- 회원은 상단 등급 배지 또는 **내 설정 → 내 이용 등급** (`#membershipView`)에서 자기 등급·기간·사용량만 확인합니다.
- 등급·한도·운영 메모·변경 이력은 REST에 노출하지 않는 `keychallenge_membership_private` 스키마에 보관하며 RLS를 활성화합니다. 공개 RPC는 security invoker이고 제한된 private 진입 함수만 호출합니다. private 함수는 `auth.uid()` 및 DB의 기존 관리자 역할을 확인하며, 브라우저에 직접 테이블 수정 권한을 주지 않습니다.
- 저장 용량은 DB 트리거에서 계정별 잠금으로 검사하므로 직접 REST 요청에도 적용됩니다. 검색 횟수도 서버에서 잠금 후 증가시킵니다. 등급 만료·한도 변경은 JWT 재발급과 무관하게 다음 요청에 반영됩니다.
- 등급·한도 수정에는 revision을 사용해 다른 관리자의 변경을 덮어쓰지 않도록 합니다. 충돌하면 최신 내용을 다시 불러온 뒤 저장합니다.


## 12. 내 블로그 분석과 검색 노출 점검

`add_blog_analysis`, `add_blog_search_free_guard`, `fix_blog_api_key_validation`, `separate_manual_blog_search`, `simplify_blog_refresh_and_daily_checks`, `collect_blog_posts_on_login` 마이그레이션을 순서대로 적용하고 `keychallenge-blog-sync`, `keychallenge-blog-search` 함수를 배포합니다. 다른 프로젝트에 설치할 때 `dispatch_blog()`의 프로젝트 URL을 변경합니다.

- **내 설정**에서 일반 블로거·인플루언서 모두 블로그 주소를 연결할 수 있습니다. 일반 블로거의 첫 대시보드는 분석 화면, 인플루언서는 기존 키챌 대시보드입니다. 공통 메뉴는 `#blogAnalysisView`입니다.
- 모든 연결된 블로그는 **로그인하거나 로그인 상태로 사이트에 접속할 때** 새 글을 수집합니다. 블로그 등록/주소 변경 시에도 수집을 요청합니다. 기존 04:30 KST 정기 수집은 비활성화했습니다. 자동 수집은 기본이며 별도 체크박스가 없습니다. 분석 화면을 열거나 브라우저를 새로고침할 때도 RSS 수집을 요청합니다. 최근 수집/요청 1분 이내에는 생략하고, 이미 대기/진행 중인 수집은 재사용합니다. 동일 사용자에 대한 인증 토큰 갱신·필터·페이지 이동·진행 상태 조회는 새 수집을 요청하지 않습니다. 1분마다 대기 작업이 있을 때만 RSS 수집과 수동 검색 점검을 각각 최대 2개씩 처리합니다. 요청한 작업은 사이트나 컴퓨터를 닫아도 완료까지 처리합니다.
- 공개 RSS에서 최대 100개 항목을 읽고 글 ID로 중복을 제거해 누적합니다. 첫 연결은 RSS 제공 범위부터 시작하므로 전체 과거 글 수가 아닙니다. RSS 오류는 기존 글을 삭제하지 않으며 최대 3회 시도합니다.
- 검색 점검은 회원이 **검색 노출 점검** 버튼을 눌렀을 때만 실행합니다. 먼저 RSS에서 새 글을 가져온 뒤 최신 **20개**에 대해 제목과 제목 앞부분(최대 6단어), 검색어별 정확도순 최대 100개 결과에서 블로그 ID + 글 ID가 일치하는지 봅니다. 하나의 검색어에서 찾으면 중단합니다. 링크의 모바일/PC/파라미터 주소를 정규화합니다.
- 상태는 `검색 확인`, `조회 범위에서 미확인`, `확인 대기`, `조회 실패`입니다. 검색어·조회 범위·반환 수·마지막 확인 시각과 직전 정상 결과를 저장합니다. 누락/저품질 판정이나 실제 통합검색 순위로 사용하지 않습니다.
- 검색 API 미연결 상태에서도 RSS 수집은 실행됩니다. 관리자는 **관리자 설정 → 블로그 검색 노출 점검 연결**에 네이버 클라우드 NAVER API HUB의 **블로그** API Client ID/Secret을 입력합니다. **검색광고 API와 별도**입니다. HUB 엔드포인트 `https://naverapihub.apigw.ntruss.com/search/v1/blog`와 `X-NCP-APIGW-API-KEY-ID` / `X-NCP-APIGW-API-KEY` 헤더를 사용합니다. 연결 저장·무료 정책 재확인·화면 열기·RSS 수집은 검색 API를 호출하거나 검색 작업을 만들지 않습니다. 회원이 요청한 검색 작업만 한도 확인 후 실행합니다.
- API 키는 Vault에 보관하고 서비스 역할의 제한된 RPC만 읽습니다. 관리자 권한을 서버에서 확인한 후 연결/중지합니다. 키는 브라우저로 반환하거나 로그에 기록하지 않습니다.
- 개인 수집 결과는 본인 UID 기반 RLS, 클라이언트 읽기 전용입니다. 갱신 요청은 로그인한 UID를 검사하는 제한된 진입 함수만 허용합니다. 워커 쓰기는 서비스 역할 전용이며 임대 토큰과 유효 시간을 확인합니다. 주소 변경/연결 해제는 진행 중인 이전 작업을 무효화합니다.
- 기본/플러스 모두 동일한 무료 기능입니다. 검색 점검은 계정당 한국시간 하루 **3회**이며 자정에 초기화됩니다. 한 번의 요청으로 최근 20개를 점검하고, 남은 횟수를 화면에 표시합니다. 기존 글별 24시간/요청별 1시간 대기는 제거했습니다. 한 작업의 첫 검색 API 호출 예약 시 계정 사용량을 1회 차감하며 이후 실패해도 되돌리지 않습니다. 글 수집 실패·점검할 글 없음·호출 전 공용 한도 차단은 계정 횟수를 차감하지 않습니다. 별도 `keychallenge_blog_check_usage`에 UID/한국 날짜별로 저장하므로 블로그 변경이나 연결 해제로 횟수를 초기화할 수 없습니다. 공용 검색 호출은 전체 회원 합산 **한국시간 일 20,000회·월 600,000회** 상한이며 DB 제약으로 이를 넘는 설정을 차단합니다. 모든 검색 직전에 하나의 상태 행을 잠가 호출 횟수를 선차감합니다. 실패·타임아웃도 차감하며 재연결/정책 확인 시 사용량을 초기화하지 않습니다. DB 확인 실패 시 호출하지 않습니다.
- 관리자는 키온 전용 API HUB 애플리케이션에 **네이버 콘솔 → Application → 한도 및 알림 → 일 20,000회·월 600,000회**를 별도로 설정하고, 현재 무료 범위가 이보다 크거나 같음을 확인해야 합니다. 이 확인 후 30일간 수동 점검을 사용할 수 있으며 기한이 지나면 재확인 전까지 중지합니다. 키온이 다른 서비스의 사용량이나 향후 요금 변경을 자동 확인할 수 없으므로 네이버 측 한도 설정과 운영자의 현재 정책 확인을 함께 사용합니다.
- 일/월 한도 도달 시 요청을 종료하며 기간이 초기화되어도 자동 재개하지 않습니다. 회원이 버튼으로 새 요청을 해야 합니다. 네이버 429 응답이면 이번 달 검색을 중지하고, 401/403 응답이면 관리자가 연결을 수정할 때까지 중지합니다. 검색 중지 중에도 로그인·분석 화면 접속 시 RSS를 수집하며 기존 검색 결과를 미확인으로 바꾸지 않습니다. 관리자 화면에서 일/월 누적 사용량, 중단 사유, 재확인 기한을 확인할 수 있습니다.
- 현황의 검색 확인/미확인/오류/대기는 최근 20개 기준입니다. 새 글은 당일 첫 발견 기준이며 발행일과 다릅니다. 발행 흐름은 수집된 글의 최근 28일, 평균 간격은 최근 20개 중 발행일이 있는 글로 계산합니다.
- RSS는 기존 모니터에서, 검색은 별도 `keychallenge_blog_search_jobs`에서 처리합니다. 검색 요청은 로그인한 본인만 만들 수 있고, 서버가 회원별 행 잠금으로 연속 클릭을 막습니다. 요청은 1시간 안에만 실행합니다. 블로그 주소 변경 시 이전 작업의 임대 토큰을 무효화합니다.
- API 호출 예약은 살아 있는 수동 요청·현재 글·검색어 중복 여부를 확인한 뒤 계정별 일 3회와 공용 무료 한도를 같은 트랜잭션에서 처리합니다. 모니터 → 요청 → 글 → 계정 사용량 → 공용 한도 순서로 잠가 동시 요청을 직렬화합니다. 한 글당 최대 두 검색어만 예약하며, 중단된 워커가 같은 검색어를 다시 호출하지 않습니다. 기존 공용 예약 RPC는 단독 검색 호출을 허용하지 않습니다.
- 방문자 수, 체류 시간, 네이버 내부 블로그 지수, 본문 분석은 포함하지 않습니다.

## 인플루언서 키워드 기회 찾기

keychallenge_keyword_opportunities는 본인 인플홈과 공개된 최신 목록, 최근 30일 안의 검색량만 읽는 SECURITY INVOKER 함수입니다. 분야별 10개 이상의 유효 표본과 월 검색량 최소 10회를 요구하며 미수집 값을 0으로 가정하지 않습니다. 내 분야는 참여 기록에서 추정하고 기록이 없으면 관심 분야를 사용합니다. 미완료 수집은 미참여 대신 참여 확인 전으로 표시합니다.

- 블루오션: 분야 검색량 중간값 이상, 참여자 중간값 이하, 검색량/(참여자+1)이 상위 25%.
- 레드오션: 검색량과 참여자가 모두 상위 25%이며 참여자가 중간값보다 큼.
- 롱테일: 대상·목적·조건 표현과 별도의 주제 표현이 있는 후보 중 검색량 상한이 분야 중간값 이하. 규칙 기반 후보이며 검색 의도를 보장하지 않습니다.
- 탭별 최대 10개를 내 분야, 미참여, 추천 지표순으로 정렬합니다. 기존 보관 RPC를 사용하므로 RLS·중복 방지·회원 한도를 그대로 적용합니다. 네이버 API 호출은 발생하지 않습니다.


### 일반 블로거의 키워드 기회 찾기

- 일반 블로거 대시보드에서도 블루오션(기본)·롱테일·레드오션 탭을 제공합니다.
- 관심 분야의 최신 검색량·키챌 참여자 지표를 비교하며, 수집된 최근 글 최대 50편의 제목에 없는 키워드를 우선합니다.
- 최근 제목에서 공통 표현을 찾아 관련 후보를 다음 순서로 우선하고 추천 이유에 표시합니다. 단순 제목 포함·단어 비교이므로 본문이나 과거 전체 이력을 판정하지 않습니다.
- 관심 분야 미설정 시 설정 링크를, 수집된 글이 없을 때는 작성 여부 비교 전 안내를 제공합니다.
- 추천 조회는 저장된 데이터만 사용하며 검색 API를 호출하지 않습니다. 기존 보관함 저장 RPC와 회원 한도를 그대로 적용합니다.
- DB 함수: `keychallenge_blogger_keyword_opportunities()`. 호출자의 블로그·글·보관함만 읽는 SECURITY INVOKER 함수입니다.
